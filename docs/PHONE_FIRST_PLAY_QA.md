# 휴대폰 첫 플레이 수정·검수

2026-09-27. 사용자가 크롬에서도 화면 오른쪽 잘림과 우유 투입 장면 가림을 재현했고, 8세 어린이가 약 1분 플레이한 뒤 어렵고 재미없다고 중단했다고 알려 주었다.

## 재현한 원인

- 화면 폭 280px에서 문서의 최소 폭이 320px로 고정되어 오른쪽 40px이 잘렸다. 게임 화면 자체가 가로 스크롤을 막고 있어 잘린 부분에 접근할 수도 없었다.
- 320×568 조리 화면에서 냉장고 재료 창은 화면 y=240~327px, 우유를 붓는 목표는 y=286~385px였다. 재료 창이 조리 장면을 직접 덮었다.
- 첫 주문은 요리 선택, 보관 장소 찾기, 재료 선택, 드래그 조리, 접시 꾸미기를 거쳐야 했다. 첫 1분에 무엇을 눌러야 하는지 알아내는 단계가 많았다.

## 바꾼 점

- 320px 최소 폭을 제거하고 280px 이하에서 상단 버튼·글자·내비게이션을 줄였다. 359px 이하의 접시 장식 선택은 가로로 잘리지 않도록 세 칸으로 배치했다.
- 재료 보관소를 열면 재료 선택 화면으로 전환한다. 선택 후에는 조리 장면이 다시 전체로 보인다. 조리대와 재료 창이 겹치지 않는다.
- 식당의 `첫 주문 바로 만들기`로 주문 요리에 곧장 들어간다. 진행 중인 요리가 있으면 `하던 요리 이어하기`로 표시한다.
- 현재 필요한 재료를 큰 `재료 넣기` 버튼으로 보여 준다. 재료가 없으면 같은 자리에서 마트로 이동한다. 보관소를 직접 여는 경로도 유지한다.
- 조리 도구를 한 번 또는 두 번 눌러 진행할 수 있다. 기존 드래그와 키보드 조작도 사용할 수 있다. 우유 단계에서는 우유 그림이 도구로 보이고, 붓기 진행에 따라 그릇 속 우유가 드러난다. 과일 요거트를 쌓을 때 나오던 토스트 그림도 해당 요리 그림으로 바꿨다.

## 검수

- Chromium 자동화에서 280×568, 320×568, 360×740, 390×844, 430×932의 문서·게임·재료 창이 화면 오른쪽 경계를 넘지 않는지 확인했다.
- 320×568에서 우유를 고를 때 조리 장면이 재료 창 뒤에 남지 않으며, 선택 뒤 그릇과 우유 도구가 보이는지 확인했다.
- 새 프로필로 첫 주문 바로 시작 → 달걀 넣기 → 도구 누르기 → 식용유 넣기 → 두 번 누르기 → 접시 완성 → 손님 서빙을 280px에서 확인했다. 320px 모바일 터치 입력도 확인했다.
- `npm test` 37개, `npm run lint`, `npm run build`, 전체 브라우저 테스트 16개 통과. 마지막 좁은 화면 배치 수정 뒤 관련 브라우저 테스트 4개를 다시 통과했다.

자동화는 아이가 재미를 느끼는지 판정하지 못한다. 동일한 아이에게 다시 짧게 해 볼 기회를 주고, 첫 주문을 스스로 끝낼 수 있는지와 어느 순간 그만두고 싶은지 관찰해야 한다. 재플레이는 강요하지 않는다.
