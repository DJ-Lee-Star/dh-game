# 냥냥식당 v2 일괄 개편 실행 계획

상태: 2026-09-27 계획의 0~6단계 실행 완료. 범위는 [다음 개편 요구사항](NEXT_REVISION_NOTES.md)의 M·C·R·G·D·P·F·K·A 항목 전체다. 단계별 실행 결과, 자동 테스트, 화면 증거 및 실제 어린이·물리 기기 검증의 미수행 항목은 [v2 QA 보고서](V2_QA_REPORT.md)에 기록했다.

## 목표와 실행 기본값

- 7~11세가 부담 없이 반복 플레이하는 모바일 웹게임을 유지한다. Lv.1~5를 완결된 범위로 만들고, 짧은 조리·선택·반응·성장 경험을 연결한다.
- 현재 React/Vite 화면은 개선해 사용한다. 게임 규칙과 콘텐츠는 데이터 중심으로 분리해 레시피·재료·손님·가족·조리 단계·보상을 한곳에서 검증할 수 있게 한다.
- 여러 플레이어의 기록은 로컬 게임 서버의 SQLite DB에 `player_id`별로 저장한다. 로그인이나 온라인 멀티플레이는 이번 범위에 넣지 않는다. 브라우저별 손님 프로필을 만들고, 같은 기기에서 여러 프로필을 전환할 수 있게 한다. 서버는 각 프로필의 접근 토큰을 확인한 뒤 해당 기록만 읽고 바꾸며 초기화한다. 외부 공개 배포에는 별도 인증 설계가 필요하다.
- 현재 `localStorage` 기록은 백업하고, 사용자가 현재 프로필로 한 번 가져올 수 있게 이전 경로를 제공한다. 가져오기 완료를 확인하기 전까지 기존 Lv.1~5 진행·코인·보유 아이템을 지우지 않는다.
- 식재료 가치·미니게임 보상·가족 선호 보상·꾸미기 가격은 콘텐츠 표에 먼저 적고, 소프트락이나 무한 보상 없이 실제 플레이로 조정한다.
- 8세 플레이어의 취향은 미리 단정하지 않는다. 음악·재미의 객관적 동작은 자동 검증하고, 실제 아이의 선호와 실제 기기 청취 결과는 마지막 사용자 확인 항목으로 분리한다.

게임 규칙과 경제는 단위/통합 테스트로, 사용자 여정은 브라우저 E2E로 검증한다. 점수·보상·재고에는 경계값과 반복 시뮬레이션을 추가한다. 모바일 브라우저 에뮬레이션을 사용하되, 에뮬레이션 통과를 실제 iOS/Android 기기 검증으로 표시하지 않는다.

완료 판정은 모든 요구 ID의 구현·검증 기록이 있고, 자동 테스트·lint·build가 통과하며, 진행 불가·기록 손실·중복 지급·다른 프로필 접근 같은 중대 문제가 0건일 때 한다. 실제 어린이 취향과 물리 기기에서의 소리·조작감은 수행 여부를 별도로 보고한다.

## 중간 개입 없이 진행하는 방식

1. 실행 중 필요한 소규모 결정은 위의 기본값과 요구사항을 기준으로 직접 내리고 결정 기록에 이유를 남긴다. 진행 보고는 남기되, 단계마다 승인받느라 멈추지 않는다.
2. 외부 계정·유료 서비스·배포 권한이 필요한 선택은 피하고 로컬에서 완성 가능한 도구와 에셋을 사용한다. 사용자의 기존 저장 기록을 검증 대상으로 삼아 초기화하지 않는다.
3. 단계 통과 조건이 실패하면 바로 수정하고 해당 단계 및 영향받은 이전 시나리오를 재검증한다. 마지막에 통과한 명령·브라우저 시나리오·스크린샷·남은 제한을 인계한다.
4. 실제 아이의 재미와 음색 취향, 실제 휴대전화의 체감 성능은 사용자나 기기에 접근하지 않고 확정할 수 없다. 나머지 구현·자동/브라우저 검증은 끝까지 수행하고, 그 확인 항목만 최종 결과에 분명히 남긴다.

## 최종 산출물

- 실행 가능한 프런트엔드와 로컬 서버, DB 마이그레이션/백업 방법, 이전 저장 가져오기, 플레이어별 초기화.
- 레벨·레시피·경제·가족 선호·미니게임·꾸미기 수치표, 원본을 포함한 아트/음향 자산 목록.
- 자동 테스트, 브라우저 시나리오와 화면 확인 결과, `test`·`lint`·`build` 실행 로그, 실행/검증 방법과 남은 제한을 담은 QA 보고서.
