# 냥냥식당 v2

7~11세가 시간 제한 없이 즐기는 모바일 웹 요리 게임입니다. 손님의 주문을 받고, 마트 진열대에서 재료를 장바구니에 담고, 주방에서 조리한 뒤 손님이나 가족에게 대접합니다. Lv.1~5와 비밀 요리, 재료 받기 놀이, 꾸미기, 짧은 이야기를 포함합니다.

식당 구도, 가족, 마트, 직접 조리, 전체 그림과 미니게임 경고를 [v2 후속 개편 계획](docs/V2_FOLLOWUP_PLAN.md)에 따라 구현했습니다. 새 화면·테스트 결과는 [후속 개편 QA 보고서](docs/V2_FOLLOWUP_QA_REPORT.md), 이어 작업할 때의 주의사항은 [최신 핸드오프](HANDOFF.md)에 있습니다.

## 실행

Node.js 24 이상이 필요합니다. 이 버전은 Node 내장 SQLite를 사용합니다.

```powershell
npm ci
npm run dev
```

브라우저에서 `http://127.0.0.1:5173/`을 엽니다. `npm run dev`는 Vite와 로컬 API 서버(`127.0.0.1:4174`)를 함께 실행합니다. 첫 화면에서 새 셰프 프로필을 만듭니다. 게임 데이터는 `data/nyanyang.sqlite`에 프로필별로 저장됩니다. 이 디렉터리는 Git에 포함되지 않습니다.

배포용 로컬 실행은 다음과 같습니다.

```powershell
npm run build
npm run start
```

그 후 `http://127.0.0.1:4173/`을 엽니다. 이 주소는 이전 v1 미리보기와 같아서 같은 브라우저에 저장된 v1 기록을 읽을 수 있습니다. 이전 v1 서버가 아직 4173 포트를 사용한다면 먼저 중지하고 v2 서버를 실행하세요. `localhost:4173`과 `127.0.0.1:4173`은 브라우저 저장 공간이 다르므로 이전에 사용한 주소를 그대로 열어야 합니다. 이 서버는 빌드된 정적 파일과 API를 함께 제공합니다.

공개 서버의 자동 배포 설정은 [배포 안내](deploy/README.md)를 따릅니다. 서버 초기 설정과 GitHub Actions 비밀값을 등록한 뒤에는 `main` 푸시마다 테스트·빌드·배포가 실행되며, 플레이 주소는 <https://leedada.duckdns.org/>입니다.

## 플레이

1. 주문을 보고 주방에서 음식을 고릅니다. 첫 요리 하나로 Lv.2, 그다음 두 요리로 Lv.3에 도달합니다.
2. 냉장고, 간식 선반, 상온 보관장을 열어 필요한 재료를 순서대로 넣습니다. 0개 재료는 회색과 `없음` 글자로 표시합니다.
3. 화면의 재료나 도구를 잡아 표시된 목표까지 옮긴 뒤 음식에 맞게 씻고, 썰고, 젓고, 굽습니다. 손동작이 어려우면 `손 모양 시범 보기`를 켜 목표를 확인하고 넓은 판정 범위에서 다시 시도할 수 있습니다. 접시에서 장식과 모양을 고르고 직접 올립니다.
4. 주문에 맞으면 손님에게 서빙하고 식사 반응을 봅니다. 다른 요리는 엄마, 아빠, 동생 중 한 명에게 대접할 수 있으며 원래 주문은 유지됩니다.
5. 곰 주인아저씨 계산대에서 오른쪽 진열대로 움직이며 재료를 고릅니다. 아래 장바구니에서 수량·합계를 보고 계산대로 돌아와 구매합니다. 재료 받기 놀이 참가비는 100코인이며, 완료 보상은 점수에 따라 최소 135코인어치입니다.
6. 코인이나 하트로 의상, 모자, 장신구, 식당 배경을 얻고 바꿀 수 있습니다. 일반 손님 주문 네 번 뒤에는 스페셜 손님 별님이 찾아옵니다.

설정에서 BGM과 효과음을 각각 끄거나 음량을 조절할 수 있습니다. 브라우저의 자동 재생 제한 때문에 첫 화면 조작 뒤에 음악이 시작됩니다.

## 프로필, 이전 기록, 백업

같은 브라우저에서 여러 셰프 프로필을 만들고 설정에서 전환할 수 있습니다. 게임 진행은 SQLite에, 프로필 접근 토큰과 오디오 설정은 해당 브라우저의 `localStorage`에 둡니다. 브라우저 데이터를 지우면 프로필 토큰도 사라지므로 미리 보존해야 합니다. 토큰 공유는 그 프로필에 대한 접근을 허용합니다.

기존 v1 브라우저 기록이 있으면 v1을 사용한 주소에서 v2를 열고 새 프로필을 만든 다음 **설정 → 이전 기록 가져오기**를 한 번 실행합니다. 기존 `nyanyang-restaurant-v2` 값은 삭제하지 않습니다. 이미 플레이한 프로필에 덮어쓰지 않으며, 필요한 경우 새 프로필을 만들어 가져옵니다. `npm run dev`의 5173 포트나 다른 브라우저에서 열면 이전 4173 포트의 브라우저 기록은 자동으로 보이지 않습니다. 설정의 초기화는 현재 선택한 프로필만 확인 절차를 거쳐 초기화합니다.

실행 중인 DB의 일관된 백업은 다음처럼 만듭니다.

```powershell
npm run db:backup
npm run db:backup -- C:\backup\nyanyang-v2.sqlite
```

복원할 때는 서버를 중지하고 현재 `data/nyanyang.sqlite`와 함께 생성된 `-wal`, `-shm` 파일을 별도 보관한 뒤, 검증한 백업 파일을 새 DB 경로에 복사합니다. 먼저 원본을 덮어쓰지 않고 `NYANG_DB_PATH` 환경 변수로 복원본을 지정해 실행하고 프로필 상태를 확인하세요. 스키마는 서버 시작 시 `PRAGMA user_version`에 따라 버전 1로 준비하며, 더 새로운 DB 버전은 오류로 중단합니다.

## 검증

```powershell
npm test
npm run lint
npm run build
npm run test:e2e
```

E2E는 전용 `data/e2e.sqlite`에서 실행합니다. 최신 실제 실행 결과와 화면 증거는 [후속 개편 QA 보고서](docs/V2_FOLLOWUP_QA_REPORT.md)에 기록했습니다. 콘텐츠 수치와 보상은 [밸런스 표](docs/V2_BALANCE.md), 새 자산은 [후속 아트 조사](docs/V2_FOLLOWUP_ART_AUDIT.md)에 있습니다.

## 주요 구현 위치

- `src/v2/content.ts`: 레시피, 재료, 가족 선호, 꾸미기와 이야기 수치
- `src/v2/engine.ts`: 구매, 조리, 서빙, 보상, 저장 유효성, 이전 기록 규칙
- `server/index.ts`: SQLite 프로필, 접근 토큰, 거래와 중복 요청 방지 API
- `server/production.ts`: 기존 v1 주소인 4173 포트로 프로덕션 서버 시작
- `server/backup.ts`: 실행 중 SQLite 백업
- `src/v2/AppV2.tsx`, `src/v2/CookScene.tsx`, `src/v2/AppV2.css`: 화면과 조리·식사 모션
- `src/v2/audio.ts`: 장소별 BGM과 효과음
- `public/game/`: 캐릭터, 의상, 가족, 손님, 장소 이미지
